# 河北尚学单招成绩分析系统

> Campus Performance Analysis —— 集**校区成绩分析、学习目标对照、高职单招大类信息查询**于一体的纯静态教学管理系统。

无需后端、无需数据库、无需安装：打开网页即在浏览器本地完成全部统计、图表与达标分析。成绩文件仅在本机浏览器内解析，**不会上传到任何服务器**。

## 一、功能总览

系统由三大模块组成，全部页面统一采用**靛蓝 + 青色、毛玻璃、粒子背景、响应式布局**的视觉语言。

### 模块 1 ：校区成绩分析

| 子页 | 说明 |
| --- | --- |
| `pages/龙泉校区.html` | 龙泉校区周测成绩分析（默认数据已内置） |
| `pages/星耀校区.html` | 星耀校区周测成绩分析 |
| `pages/睿智校区.html` | 睿智校区（占位页，成绩文件就位后自动启用） |
| `pages/通用成绩分析.html` | 通用分析：手动上传任意成绩文件即可分析 |

核心能力：

- **达标率统计**：公办 / 民办分数线达标人数与占比。
- **分数段分布**：直方图呈现各分数段人数。
- **数据明细表**：全班成绩一览，支持排序、筛选、搜索。
- **个人趋势**：单个学生多次考试的成绩变化曲线。
- **分值对齐（重点）**：不同考试满分不同时，自动按「班级 × 科目历次出现过的最高满分」等比换算，使所有统计、图表、达标率统一在同一尺度；折算只影响页面计算，**不修改 Excel 原文件**。
- **一键导出**：A4 横向 PDF（按学科 / 班级批量）或 Excel。

### 模块 2 ：学习目标（`pages/learning-objectives.html`）

- 按**班级 / 考试**筛选，顶部统计条展示：参考人数、平均分、已设目标人数、达公办 / 民办人数及占比。
- 点击任意学生，弹出**个人详情**：
  1. 排名横幅（班级排名、总分、班级平均 / 最高、预估位次）；
  2. 本次各科成绩；
  3. 与上一次考试对比（分数、排名变化）；
  4. 目标院校；
  5. 按本次成绩预估可达院校；
  6. 学习建议。
- 支持上传**目标院校表**（模板见 `assets/templates/目标院校填写模板.xlsx`），与成绩自动对照。
- 默认成绩（`27届龙泉周测成绩.xlsx`）已内嵌为 `assets/js/default-grades.js`，**本地双击打开也能直接看到数据**。

### 模块 3 ：大类信息（`pages/admission-info.html`）

河北省高职单招 **2024–2026 三年数据查询系统**：

- 顶部按年份切换（2024 / 2025 / 2026），按考试大类（综合、一类 … 十类）筛选。
- 六类数据视图：**综合信息、录取分数线、招生计划、院校详情、一分一档、专业计划及学费**。
- 8 张可视化图表：各大类招生院校数、公民办招生计划、公民办最低投档分、学费区间、院校地区、公民办占比、各分数段人数、专业招生计划 TOP20。
- **三年对比视图**：按「院校 + 专业」合并三年数据，展示投档分与位次逐年变化（支持筛选、搜索、导出 CSV）。
- 点击院校名称查看院校详情弹窗。

## 三、快速开始

### 方式 A：在线访问（推荐）

部署到 GitHub Pages 后，直接访问：

```
https://<你的用户名>.github.io/Campus_Performance_Analysis/
```

### 方式 B：本地打开

1. 下载整个 `Campus_Performance_Analysis` 文件夹。
2. **学习目标页**可直接双击 `pages/learning-objectives.html`，默认成绩已内嵌。
3. 其余页面（首页、校区页、大类页）建议通过本地 HTTP 服务打开，以支持自动读取成绩文件：

```bash
# 任选其一（在项目根目录执行）
python -m http.server 8000
# 或
npx serve .
```

然后浏览器访问 `http://localhost:8000/`。

> 关于直接双击（`file://`）打开的限制，见 [第九节常见问题](#九常见问题)。

## 四、模块使用说明

### 4.1 校区成绩分析

1. 从首页点击对应校区卡片，或直接打开 `pages/` 下的校区页。
2. 页面自动读取 `data/` 中的成绩 Excel；顶栏实时显示数据来源（文件名、班级数、考试次数、学生数）。
3. 顶部筛选区选择**考试、统计方式（平均分 / 中位数等）、班级、科目**。
4. 通过功能菜单切换：达标率、数据明细、分数段分布、全班成绩、个人趋势等。
5. 找不到成绩文件时，可点击右上角「上传 Excel」用新文件覆盖，支持多文件同时上传。
6. 点击「导出」，按「功能 - 班级 / 姓名」自动命名导出 PDF / Excel。

### 4.2 学习目标

1. 打开 `pages/learning-objectives.html`，默认加载龙泉 27 届成绩。
2. 顶部「班级」「考试」胶囊切换筛选；统计条实时更新。
3. 在成绩总览表中点击任意学生，查看个人详情与达标分析。
4. 上传目标院校：点击「目标院校」上传按模板填写的 Excel，系统自动与成绩对照。
5. 可随时上传新的成绩文件替换默认数据。

### 4.3 大类信息

1. 打开 `pages/admission-info.html`，默认显示 2026 年综合数据。
2. 顶部切换年份；点击具体考试大类（如「一类」）进入该类明细。
3. 用「综合信息 / 录取分数线 / 招生计划 / 院校详情 / 一分一档 / 专业计划及学费」标签切换数据类型。
4. 搜索框可按院校、专业、地区模糊查询；「筛选」可按办学性质、地区、分数区间等过滤。
5. 点击右上角「三年对比」进入对比视图，查看投档分与位次变化。
6. 「导出 CSV」可将当前视图表格导出。

## 五、数据口径与来源

- **数据来源**：河北省教育考试院，提取自河北单招网（hbdzxx.com），**仅供参考，以官方公布为准**。
- **成绩数据**：各校区周测成绩，由教务提供，文件保存在 `data/`。
- **单招数据**：`assets/data/data_2024.js`、`data_2025.js`、`data_2026.js`，由 `tools/data-pipeline/` 中的脚本从结构化 Excel 转换而来。

### 历史数据完整度说明（重要）

经核对，源数据中：

| 年份 | 院校专业级投档分 | 一分一档 | 说明 |
| --- | --- | --- | --- |
| 2024 | 无 | 有 | 仅公布省控制线（一类 390 分等），未公布院校专业级投档分 |
| 2025 | 无 | 有 | 采集时院校专业投档分均为「—」，仅有省控制线（一类 367 分等） |
| 2026 | 有 | 有 | 含完整院校专业级投档分 |

因此：

- **三年对比视图**中，2024 / 2025 的投档分列大多为空，分数 / 位次变化（26-24）相应为空——这是源数据本身的完整度问题，并非程序错误。
- 系统如实呈现数据，**不做任何推测或填充**。

## 六、部署到 GitHub Pages

### 6.1 为什么需要 `.nojekyll`

GitHub Pages 默认用 Jekyll 处理站点，而 Jekyll 会**忽略所有以 `_` 开头的文件和目录**，并可能对中文文件名做额外处理。本项目页面与成绩文件大量使用中文名称，保留根目录的 `.nojekyll`（空文件）即可原样发布，**请勿删除**。

### 6.2 部署步骤

```bash
# 1. 在项目根目录初始化仓库
git init
git add .
git commit -m "成绩分析系统 v1.0：校区成绩 + 学习目标 + 大类信息"

# 2. 关联远程仓库（替换为你的仓库地址）
git remote add origin https://github.com/<你的用户名>/Campus_Performance_Analysis.git
git branch -M main

# 3. 推送
git push -u origin main
```

### 6.3 开启 GitHub Pages

1. 进入仓库 **Settings → Pages**。
2. **Source** 选择 `Deploy from a branch`。
3. **Branch** 选择 `main`，目录选择 `/ (root)`，保存。
4. 等待构建完成（约 1–2 分钟），访问地址为：

```
https://<你的用户名>.github.io/Campus_Performance_Analysis/
```

### 6.4 部署前自查清单

- [ ] 成绩 Excel 与页面 HTML 的相对路径正确（`data/`、`assets/`）。
- [ ] `.nojekyll` 已提交（`git status` 能看到，未被忽略）。
- [ ] 中文文件名已正确提交（`git ls-files` 检查，无乱码）。
- [ ] `node_modules/`、`_shots/` 未被提交（已在 `.gitignore` 排除）。

> 建议使用 Git for Windows 时先执行 `git config core.quotepath false`，避免中文文件名在 `git status` 中显示为转义序列。

## 七、数据更新流程

### 更新校区成绩

- 用新的成绩文件**覆盖 `data/` 下同名文件**即可，无需改代码；下次打开页面自动读取。
- 若新文件满分发生变化（如语文从 100 改为 150），只要表头按「科目（满分）」格式标注，分值对齐会自动生效。
- 若文件名改变，需同步修改页面内 `CAMPUS_CONFIG`（`dataFile` / `dataCandidates`）与 `index.html` 的 `CAMPUSES` 数组。

### 更新学习目标默认成绩

- `assets/js/default-grades.js` 内嵌默认成绩的 base64。更换默认成绩后，需重新生成该文件（将 xlsx 转 base64）。

### 更新单招数据

- 用 `tools/data-pipeline/` 中的脚本将新的结构化 Excel 转换为 `assets/data/data_<年份>.js`，并在页面中确认引用。

## 八、技术栈与第三方库

- **原生 HTML / CSS / JavaScript**：无框架、无构建步骤、无后端。
- **[SheetJS（xlsx）](https://sheetjs.com/)**：浏览器端解析 Excel。
- **[ECharts](https://echarts.apache.org/)**：大类信息数据可视化。
- **Canvas 粒子背景**：纯原生实现，页面不可见时自动暂停。

第三方库统一通过 CDN 加载（jsDelivr，备用 cdnjs）。

## 九、常见问题

**Q1：直接双击打开页面，成绩 / 图表不显示？**

浏览器在 `file://` 协议下会禁止 `fetch()` 读取本地文件（报错 `URL scheme "file" is not supported`）。
- **学习目标页**已把默认成绩内嵌为 base64，双击可直接看数据。
- 其余页面请通过本地 HTTP 服务打开（见 [第三节方式 B](#方式-b本地打开)），或直接访问部署后的 GitHub Pages。

**Q2：打开大类信息页提示 `echarts is not defined`？**

一般是 CDN 网络加载失败。系统已配置 jsDelivr 与 cdnjs 双源；若仍失败，请检查网络后刷新。

**Q3：三年对比里为什么 2024 / 2025 没有分数？**

源数据中这两年未公布院校专业级投档分（仅省控制线），见 [第五节历史数据完整度说明](#历史数据完整度说明重要)。

**Q4：成绩数据安全吗？**

所有成绩仅在本机浏览器内解析，不会上传到任何服务器；仅当你主动使用 `pages/upload.html` 并登录授权时，才会把文件同步到你自己的 GitHub 仓库。
